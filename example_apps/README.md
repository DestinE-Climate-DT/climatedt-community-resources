# Resources to Retrieve Impact-Sector Application Data

Unlike climate model data, which can be accessed through several distribution channels, application results produced within Climate DT are available exclusively through the Harmonised Data Access (HDA) API. The HDA API provides a unified interface for discovering and downloading datasets generated by the different impact-sector applications. It is built around the SpatioTemporal Asset Catalog (STAC) specification, an open standard for organising and describing geospatial datasets.

The notebooks in this folder demonstrate how to work with the HDA API for a range of impact-sector applications. Each notebook focuses on a specific use case and guides users through the complete workflow, including:

- discovering available datasets,
- filtering data based on spatial, temporal, or application-specific criteria,
- downloading the selected assets, and
- visualising the results.

Before using these notebooks, it is helpful to become familiar with a few key concepts related to STAC and how datasets are organised in the HDA API.

## STAC

The SpatioTemporal Asset Catalog (STAC) specification is an open standard for describing and cataloguing geospatial data in a consistent and searchable way. It uses a JSON-based structure that allows datasets from different providers to be discovered and accessed through a common interface.

At its core, STAC organises data hierarchically. A STAC collection groups together related datasets, while each collection contains one or more STAC items. Every item references one or more assets, which are the actual data files. This hierarchical structure makes it possible to efficiently search for data based on metadata such as geographic location, time period, variables, or other application-specific properties.

Only a small number of metadata fields are required by the STAC specification. However, it also supports a rich set of optional fields and extensions that allow data providers to include detailed information about the datasets, making them easier to understand and use.

STAC is supported by numerous software tools and programming languages, including Python, R and QGIS. While the concepts described here are independent of any programming language, the examples in this documentation focus on Python, as it is the primary language used throughout the Climate DT notebooks.

## STAC Collections

A STAC collection represents a logical group of related datasets that share common metadata and characteristics. Collections provide high-level information describing the overall dataset, including its spatial and temporal coverage, variables, licensing information, and other metadata that applies to all contained items.

For example, within Climate DT, the output of the IFS–NEMO climate model for the historical simulation period can be represented as a single STAC collection. Similarly, impact-sector applications are organised so that each application corresponds to a single STAC collection. Within that collection, outputs generated using different climate models or simulation configurations are represented by separate STAC items.

Collections therefore serve as the main entry point when searching for data, allowing users to identify the application or dataset of interest before exploring the individual items it contains.

## STAC Items

STAC items are the fundamental part of a STAC catalog. Each item represents a specific dataset or data product that shares a common spatial and temporal extent, together with a consistent set of metadata.

Every item includes information such as:

- its spatial extent (typically represented by a bounding box),
- its temporal extent or timestamp,
- descriptive metadata,
- application-specific properties, and
- references to one or more assets containing the actual data.

The temporal coverage of a STAC item is highly flexible. An item may represent data for a single point in time, a single day, an entire month, several decades, or even centuries, depending on the characteristics of the underlying dataset. Likewise, items may differ in their spatial coverage, resolution, or other metadata, allowing large datasets to be organised into manageable and searchable units.

## Assets

Assets are the actual data files associated with a STAC item. While collections and items contain metadata describing the data, assets contain the information that users ultimately download and analyse.

Assets can be stored in a variety of formats depending on the application and intended use. Common examples include:

- NetCDF 
- CSV 
- GeoTIFF 
- images 
- PDF documents or other supporting materials

When querying a STAC collection through the HDA API, users can choose to access individual assets directly or retrieve multiple assets belonging to the same item or collection. This flexibility allows users to download only the specific files required for their analysis, avoiding unnecessary data transfers while still providing access to complete datasets when needed.
